# NASAQ | نَسَق — منصة التصميم والتحرير المؤسسي

NASAQ | نَسَق منصة ويب عربية (RTL First) للتصميم والتحرير المؤسسي: تقارير ومستندات
وتصاميم رسمية بصفحات متعددة، مع محرر مرئي، ومعاينة، وحفظ محلي، وتصدير إلى PDF وPNG
وJPG وصيغ أخرى.

**الوصف بالإنجليزية:** Professional Design & Report Editor
**المطوّر:** Faisal Alenezi — من تطوير فيصل سعود العنزي

هذا المستند موجّه للمبتدئ: يشرح تشغيل المشروع على جهاز Mac خطوة بخطوة، وطريقة
رفعه مجانًا على الإنترنت، وكيفية صيانته وتطويره لاحقًا.

> **نسخة جاهزة للتنزيل:** يوجد في جذر المشروع ملف
> `nasaq-platform-source.zip` يحتوي **كامل ملفات المشروع** (بما فيها تاريخ
> Git كنسخة احتياطية). بعد فك الضغط ستحصل على مجلد `nasaq-platform/`
> جاهز للبناء أو الرفع مباشرة — لا يحتوي `node_modules` (يُعاد تثبيتها بأمر
> `npm install`). ثم أكمل من القسم 3 (التشغيل) أو القسم 6 (الرفع المجاني).

## 1. ما هو المشروع؟

محرر تصميم تقارير يعمل في المتصفح:

- **مشاريع متعددة**، كل مشروع يحتوي على **صفحات** (غلاف، مقدمة، إحصائيات، جداول، خاتمة…).
- **عناصر قابلة للتحرير**: نص، صورة، شعار، أشكال، خطوط، فاصل، جداول، بطاقات إحصائية، مؤشرات تقدّم، أيقونات، أختام، QR.
- **لوحة خصائص** لكل عنصر: الموضع، الحجم، الدوران، الشفافية، الخط، الحجم، الوزن، المحاذاة، اللون، الحدود، الاستدارة، الظل، التباعد.
- **مقاسات صفحات رسمية**: A4 رأسي/أفقي، A3، 16:9، ومقاس مخصص — مع تغيير الاتجاه.
- **تراجع/إعادة** (Undo/Redo) مع اختصارات لوحة المفاتيح.
- **حفظ تلقائي** لجميع المشاريع محليًا في المتصفح.
- **استيراد وتصدير JSON** لنقل المشروع بين الأجهزة.
- **تصدير التصميم**: PDF، PNG، JPG، HTML مستقل، Word، PowerPoint.
- **قوالب جاهزة** مصنّفة (أغلفة، تقارير رسمية، إحصائيات، جداول، مؤشرات، إنفوجرافيك، صفحات داخلية، عروض 16:9).
- **مكتبة عناصر دائمة**: احفظ أي شكل أو شعار أو صورة استخدمتها مرة واحدة، وأعد استخدامها في أي مشروع لاحق. المكتبة تبقى بعد إغلاق المتصفح ولا ترتبط بمشروع واحد، فحذف مشروع لا يحذف محتواها.
- **سحب بالماوس وتحديد متعدد**: حرّك العنصر بالفأرة، وحدّد كل عناصر الصفحة بزر واحد أو بـ ⌘A ثم اسحبها ككتلة واحدة.

الواجهة والبيانات كلها عربية ومهيّأة للاتجاه من اليمين إلى اليسار.

## 3. التشغيل على Mac — خطوة بخطوة

### الخطوة 1: افتح Terminal

من Spotlight اضغط `Cmd + Space` ثم اكتب `Terminal` واضغط Enter.

### الخطوة 2: انتقل إلى مجلد المشروع

```bash
cd /path/to/project
```

بدّل `/path/to/project` بالمسار الحقيقي. نصيحة: اكتب `cd ` ثم اسحب مجلد المشروع
وأفلته داخل نافذة Terminal ليكتب المسار تلقائيًا.

للتأكد أنك في المكان الصحيح:

```bash
ls
```

يجب أن ترى `package.json` ضمن الملفات.

### الخطوة 3: ثبّت المتطلبات

```bash
npm install
```

قد يستغرق دقيقة أو دقيقتين. هذه الخطوة تُنشئ مجلد `node_modules`.

### الخطوة 4: شغّل المشروع

```bash
npm run dev
```

ستظهر رسالة تشبه:

```
VITE ready in ... ms
➜  Local:   http://localhost:8080/
```

اترك هذه النافذة مفتوحة — إغلاقها يوقف السيرفر.

### الخطوة 5: افتح الرابط في المتصفح

افتح [http://localhost:8080](http://localhost:8080).

**كيف تعرف أن المشروع اشتغل؟** ستظهر الصفحة الرئيسية باسم **NASAQ | نَسَق** وعنوان
**صمّم تقاريرك باحتراف** وزرّي **إنشاء مشروع جديد** و**فتح مشروع**. وإن ظهرت صفحة
بيضاء، راجع نافذة Terminal وابحث عن رسالة خطأ.

### الخطوة 6: أوقف السيرفر ثم أعد تشغيله

- **الإيقاف:** ارجع إلى نافذة Terminal واضغط `Ctrl + C`.
- **إعادة التشغيل:** نفّذ `npm run dev` مرة أخرى.

لتشغيله في الخلفية دون حجز النافذة:

```bash
nohup npm run dev > /tmp/app-dev.log 2>&1 &
```

ثم لمتابعة السجل أو إيقافه:

```bash
tail -f /tmp/app-dev.log                       # متابعة السجل (Ctrl+C للخروج)
pkill -f "vite dev"                            # إيقاف السيرفر
```

### الخطوة 7: عدّل الملفات وشاهد النتيجة

افتح المشروع في محرر مثل VS Code، عدّل أي ملف، ثم احفظ. المتصفح **يُحدَّث تلقائيًا**
(Hot Reload). وإن لم يحدث ذلك، أعد تحميل الصفحة يدويًا بـ `Cmd + R`.

### الخطوة 8: ابنِ النسخة الإنتاجية

```bash
npm run build
```

الناتج يذهب إلى مجلد `.vercel/output`. ثم لتجربة النسخة الإنتاجية محليًا:

```bash
npm run preview
```

يفتح على [http://127.0.0.1:8081](http://127.0.0.1:8081). أوقفه بـ `Ctrl + C`.

## 5. أين تُحفظ المشاريع؟

تُحفظ مشاريعك **داخل متصفحك على جهازك** ولا تُرفع إلى أي سيرفر:

- **IndexedDB** (قاعدة `nasaq-reports`) — المخزن الأساسي، ويتحمّل المشاريع كبيرة الحجم
  لأن الصور تُخزَّن داخلها بصيغة data URL.
- **localStorage** — نسخة احتياطية صغيرة للبيانات الوصفية، وتُستخدم للطوارئ حين
  يكون IndexedDB معطلًا (مثل نوافذ التصفح المتخفي) فيبقى التطبيق يعمل بدل أن يفقد العمل.

**تنبيه مهم:** لأن التخزين محلي، فإن حذف بيانات المتصفح يمحو المشاريع. لذلك:

1. استخدم **تصدير JSON** بشكل دوري للاحتفاظ بنسخة آمنة.
2. عند الانتقال إلى جهاز آخر، استخدم **استيراد JSON**.

## 6. الرفع المجاني على الإنترنت

المشروع يُبنى بـ **Nitro** بتهيئة **Vercel** (انظر `vite.config.ts`)، لذا أفضل خيار
مجاني هو **Vercel** مباشرة: نشر بضغطة واحدة، HTTPS مجاني، ونطاق فرعي مجاني.

> لماذا Vercel تحديدًا؟ لأن إعدادات البناء مضبوطة عليه مسبقًا في المشروع. البدائل
> مثل Netlify أو Cloudflare Pages تحتاج تعديل إعدادات البناء، لذا ابدأ بـ Vercel.

### الخطوة 1: أنشئ حسابًا

اذهب إلى [vercel.com](https://vercel.com) وسجّل بحساب GitHub أو بالبريد الإلكتروني.

### الخطوة 2: أنشئ مستودعًا على GitHub

1. اذهب إلى [github.com/new](https://github.com/new).
2. اختر اسمًا مثل `nasaq-reports` واجعله **Private** أو **Public** كما تفضّل.
3. لا تضع علامة على "Add a README" لأن المشروع يحتوي ملفاته بالفعل.
4. اضغط **Create repository**.

### الخطوة 3: ارفع المشروع إلى GitHub

من داخل مجلد المشروع في Terminal:

```bash
git init
git add .
git commit -m "NASAQ | نَسَق — النسخة الأولى"
git branch -M main
git remote add origin https://github.com/<اسم-حسابك>/nasaq-reports.git
git push -u origin main
```

بدّل `<اسم-حسابك>` باسم حسابك على GitHub. إن طلب اسم مستخدم وكلمة مرور، فاستخدم
**Personal Access Token** ككلمة المرور (أنشئه من GitHub → Settings → Developer
settings → Tokens).

> ملف `.gitignore` في المشروع يمنع رفع `node_modules` و`.vercel` تلقائيًا.

### الخطوة 4: اربط المشروع بـ Vercel

1. من لوحة [vercel.com](https://vercel.com) اضغط **Add New… → Project**.
2. اختر **Import Git Repository** ثم اختر مستودع `nasaq-reports`.
3. امنح Vercel صلاحية الوصول للمستودع إن طُلبت.

### الخطوة 5: إعدادات البناء

Vercel يكتشف المشروع تلقائيًا، لكن تأكد من:

| الإعداد | القيمة |
| --- | --- |
| Framework Preset | `Vite` (أو `Other`) |
| Build Command | `npm run build` |
| Output Directory | `.vercel/output` |
| Install Command | `npm install` |
| Node.js Version | `20.x` أو أحدث (من Settings → General) |

لا تحتاج إلى متغيّرات بيئة (Environment Variables) للعمل الأساسي.

### الخطوة 6: انشر

اضغط **Deploy** وانتظر انتهاء البناء (عادة أقل من دقيقة). تابع السجل مباشرة في
نفس الصفحة.

### الخطوة 7: احصل على الرابط

بعد نجاح البناء سيعطيك Vercel رابطًا مثل:

```
https://nasaq-reports.vercel.app
```

جرّبه، وتأكد من ظهور الصفحة الرئيسية والمحرر وتصدير PDF.

### الخطوة 8: حدّث الموقع مستقبلًا

كل مرة تعدّل المشروع محليًا:

```bash
git add .
git commit -m "وصف التعديل"
git push
```

سيكتشف Vercel التغيير وينشر تلقائيًا. لمتابعة حالة النشر: لوحة Vercel →
Deployments.

### النشر من الطرفية (بديل)

```bash
npm i -g vercel
vercel          # نشر تجريبي
vercel --prod   # نشر نهائي
```

## 7. هل أحتاج Backend؟ وحدود المجانية

**لا تحتاج Backend لتشغيل المنصة.** مشاريعك تُحفظ في متصفحك، والتصدير يتم داخل
المتصفح. لذا يعمل الموقع على أي استضافة ثابتة مجانية.

المشروع يتضمن طبقة مصادقة اختيارية (Better Auth) وطبقة بيانات (PGLite محليًا /
Postgres عند ضبط `DATABASE_URL`). هذه **غير مطلوبة** لاستخدام المحرر، وتُترك معطّلة
افتراضيًا ما لم تضبط متغيّرات البيئة.

**حدود خطة Vercel المجانية (Hobby):** مخصّصة للاستخدام الشخصي وغير التجاري، مع
حدود شهرية على النقل (Bandwidth) وعدد عمليات البناء. كافية تمامًا لاستخدام شخصي.

**متى تحتاج ترقية؟** إذا أردت لاحقًا: حسابات مستخدمين، مزامنة المشاريع بين أجهزة
مختلفة، أو تعاونًا بين أكثر من شخص. حينها تحتاج قاعدة بيانات (Neon/Postgres) وخطة
مدفوعة عند تجاوز الحدود. **لا تُضِف أي خدمة مدفوعة إلا بعد قرارك الصريح.**

## 8. الأمان

- **لا توجد مفاتيح أو كلمات مرور في كود الواجهة.** كل ما يظهر في `src/` هو منطق
  تصميم وتصدير فقط. متغيّرات البيئة الحساسة (مثل `DATABASE_URL`) تُقرأ على السيرفر
  فقط ولا تُرسل إلى المتصفح.
- **لا يُستخدم `dangerouslySetInnerHTML`** ولا `eval` في المشروع.
- **تصدير HTML** يُعالج بيانات المشروع كمدخلات غير موثوقة: القيم الرقمية تُقيَّد،
  وقيم الأنماط النصّية تُطابق قائمة مسموحة، والنصوص تُهرَّب. لذلك استيراد ملف
  `.json` من جهة خارجية ثم تصديره لا يسمح بحقن سكربت في الملف الناتج.
- **مصادر الصور** تمرّ عبر دالة واحدة (`safeImageSrc`) عند فتح المشروع ويستخدمها
  العرض والتصدير معًا، فتسقط `javascript:` و`data:text/html` ولا تصل إلى الصفحة.
- **الرفع:** لا يوجد رفع ملفات إلى سيرفر — الصور تُقرأ محليًا وتُخزَّن في مشروعك فقط.

إن أردت لاحقًا إضافة مصادقة حقيقية أو تكامل خارجي، فاحفظ الأسرار في متغيّرات بيئة
على السيرفر (Vercel → Settings → Environment Variables) ولا تضعها في الكود أبدًا.

## 9. الصيانة والتطوير المستقبلي

### خريطة الملفات

```
src/
├── components/
│   ├── editor/          # واجهة المحرر
│   │   ├── EditorApp.tsx      # الهيكل العام: الشريط الجانبي + اللوحة + منطقة التصميم
│   │   ├── CanvasStage.tsx    # منطقة التصميم والمعاينة
│   │   ├── ElementNode.tsx    # عرض عنصر واحد وتحريكه وتغيير حجمه
│   │   ├── LeftPanel.tsx      # إضافة العناصر والقوالب والخطوط
│   │   ├── RightPanel.tsx     # خصائص العنصر المحدد
│   │   ├── PageRail.tsx       # الصفحات: إضافة/حذف/نسخ/ترتيب
│   │   └── ExportDialog.tsx   # نافذة التصدير
│   ── site/            # صفحات الموقع (رئيسية، مشاريع، قوالب، عن، تواصل)
├── lib/
│   ├── brand.ts         # هوية المنصة ورقم التواصل ورابط واتساب
│   ├── editor/
│   │   ├── model.ts     # أنواع البيانات، مقاسات الصفحات، العمليات
│   │   ├── store.ts     # حالة المحرر (zustand) + التراجع والإعادة + الحفظ التلقائي
│   │   ├── storage.ts   # التخزين في IndexedDB و localStorage
│   │   ├── templates.ts # القوالب الجاهزة
│   │   ── export.ts    # PDF / PNG / JPG / HTML / Word / PowerPoint / JSON
│   └── og/              # بيانات بطاقة المشاركة
── routes/              # مسارات الصفحات
```

### قواعد مهمة عند التعديل

1. **هوية المنصة ورقم التواصل:** عدّل `src/lib/brand.ts` فقط، ولا تكرّر الرقم في
   ملفات أخرى.
2. **مقاسات الصفحات:** تُعرَّف في `src/lib/editor/model.ts`، فأي مقاس جديد يُضاف
   هناك ليظهر في كل الواجهة.
3. **القوالب:** أضفها في `src/lib/editor/templates.ts`. كل قالب مُعرَّف كدالة تُرجع
   صفحات جديدة، لذا اختياره يُنشئ نسخة مستقلة ولا يعدّل القالب الأصلي.
4. **الحفظ:** يتم تلقائيًا. لا تكتب حفظًا يدويًا في الواجهة.
5. **العناصر الجديدة:** أضف النوع في `model.ts` ثم اعرضه في `ElementNode.tsx`
   وخصائصه في `RightPanel.tsx` وطريقة تصديره في `export.ts`.

### قبل كل إصدار

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

### ملاحظة حول اختبارات المشروع

يوجد **16 اختبارًا فاشلًا مسبقًا** في `npm test` ضمن ملفات `scripts/*.test.mjs`.
هذه الاختبارات تتحقق من وجود ملفات توثيق خاصة ببيئة التطوير الأصلية
(`.grok/skills/…`) وهي **غير موجودة في هذا المستودع**، ولذلك تفشل. هذه حالها قبل
التطوير وبعده ولم تتأثر بأي تعديل — لا تقلق منها، ولا تحذفها.

### نسخة احتياطية

قبل أي تعديل كبير، أنشئ فرعًا في Git:

```bash
git checkout -b my-change
```

وإن أردت الرجوع عن تعديل:

```bash
git status          # ما الذي تغيّر؟
git diff            # تفاصيل التغيير
git checkout -- .   # إلغاء كل التعديلات غير المحفوظة
git stash           # تجنيب التعديلات مؤقتًا
```

النسخة الأصلية قبل التطوير محفوظة في وسم Git باسم `baseline-original`:

```bash
git show baseline-original:src/components/editor/EditorApp.tsx   # عرض ملف من النسخة الأصلية
git diff baseline-original --stat                                # ملخص كل ما تغيّر
```

| التصدير يستغرق وقتًا | تصدير PNG/PDF يُنتج صورة لكل صفحة، لذا وقت التصدير يزيد مع عدد الصفحات |
| خطأ في `npm run build` | نفّذ `npm run typecheck` أولًا لرؤية الخطأ الحقيقي |
| **`502 Bad Gateway` على رابط المعاينة** | هذا خاص ببيئة التطوير السحابية: الرابط العام يوجّه إلى المنفذين `12000` و`12001`، بينما Vite يستمع على `8080`. شغّل `node scripts/preview-bridge.mjs` (يعمل تلقائيًا عبر `/workspace/startup.sh`). على جهازك المحلي لا تحتاج هذا — افتح `http://localhost:8080` مباشرة |
